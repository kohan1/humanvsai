the training behind it

inside

Every run that produced the three opponents on this site — including the ones that failed. Each opponent is a neural network, not hand-written rules. Snake and Tetris got there by reinforcement learning: playing their own game millions of times and being scored on the result (Snake after first copying a hand-written player). Watermelon's is a copy — a network trained to imitate a hand-written heuristic — because once the game's fruit sizes were fixed, thirty million steps of reinforcement learning on top of that copy added nothing measurable.

When a "new best" is only luck

While it trains, the model stops every 250,000 steps, plays a fixed set of games, and saves a copy whenever it beats its best so far. Keeping the best rather than the last has paid off: on the 20M-step GPU run the saved best measured 1032.43 against 959.93 for the model the run ended on. This run shows where that stops working.

This is Watermelon's 100M-step second attempt, stopped at 79M. Left to right is training progress; each dot is one check of the same fifteen games. On identical games the score swings by hundreds of points — 751 to 1,136 across 316 checks. The dashed line is the model the run started from, scored on those same fifteen: 1,123, because it had itself been saved as the luckiest check of the run before. Over 60 games it scores 1,042. Twice a check edged past 1,123, by 7 and by 12 points — a fraction of that swing — and the run saved each as a new best. Re-measured on more games they scored 1,015.80 and 996.78: both worse than where the run started. A best picked on a few fixed games is partly a pick of which model those games happened to flatter. Checks now play 40 games rather than 15, and no model replaces the one on the site until it has been measured separately.

How good it got, for how much training

Every finished run, scored over 30 to 60 full games after it ended. This is the headline question — does more training actually buy more skill?

Sideways is total training, not the length of one run: a run that continues from an earlier model inherits everything that model already learned, so 4M steps on top of a 10M-step model sits at 14M. Up is the score it achieved. The line only joins versions that were kept and built on — a run that scored worse was discarded, so nothing was ever built on top of it, and joining it to the line would suggest otherwise. Hover any point for what changed in that run, what it bought per million steps, and whether its weights still exist to be played.

Watermelon has a break in it. Its fruit sizes were changed after the earlier runs: two of the largest fruit could never fit in the well together, so they could never merge and clear, and every game was bound to fill up however well it was played. That made it a different game. The model after the break scores about four times higher because the game changed, not because training paid off — the unchanged hand-written heuristic improved by a similar factor — and it was trained afresh by imitation rather than continued from the runs before it. So it gets its own panel and its own scale.

The family tree

Training did not run in a line. Every run starts from some earlier model, and when one came out worse it was abandoned and the next attempt went back to the last good version instead.

Each dot is one training run, placed left to right by how much total training it represents, with its evaluated score beside it. A curve joins a run to the model it started from. The straight row along the top is the line that was kept and built on. Everything hanging below it is a branch that stopped: usually a run that finished below the model it started from, so it was kept as a record and never built on. Runs with no score were stopped before they were worth measuring. Watermelon's line restarts after a break: the fruit sizes changed, which made it a different game, and the model the site serves was trained afresh on it rather than continued from anything to the left.

What the network actually is

Read straight out of the model files the site ships, so it cannot drift from what is really running.

Read left to right: numbers describing the board go in one end, and a score for every move the AI could make comes out the other. Each box in between is a layer of the network, and its figures are the shape of that layer's weight matrix — outputs × inputs. So 1024 × 238 means 1,024 units each looking at all 238 input numbers, which is where its 243,712 weights come from. A convolution layer slides one small filter across the board, so it learns shapes wherever they appear; a dense layer connects everything to everything. Snake and Watermelon see a grid and use both; Tetris is dense throughout. Every one of those weights started as a random number and was moved only by playing.

How fast it trains

Watermelon training speed in steps per second, measured with the real training loop on a Ryzen 7 3700X and an RTX 4060 Ti, by how many games run in parallel. Twenty was the fastest setting in both rounds of measurement. Doubling the observation to the 2,652 numbers the site's model reads cost 25–45% of the speed.

The Tetris bot's actual brain

Not a diagram of a neural network — this one. Every line is a real weight read out of the model file the site ships, drawn at its true strength: blue pulls an option up, red pushes it down. Hover a neuron to isolate what it is connected to.

Each column is a layer, each dot one neuron, and each line a real connection between them. Numbers describing the board enter on the left and a score for every possible move leaves on the right. A neuron brightens as it fires, and a line is only lit while the neuron feeding it is active — so you are watching signal find a path, not a loop of decoration. Most neurons sit dark at any moment, which is genuinely how this kind of network behaves. Hover any neuron to mute everything except its own connections.

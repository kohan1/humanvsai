Every run that produced the three opponents on this site — including the ones that failed. Nothing here is hand-written behaviour: each model learned by playing its own game several million times and being scored on the result.

Learning curves

Score against training steps, straight out of the logs. Click a run to hide it; hover for the numbers.

Why the best model is not the last one

The current run scores itself every 250,000 steps on a fixed set of games, so the checks are directly comparable. The result swings wildly between checks even though the games never change — which is exactly why training keeps the best model it has seen rather than whatever it happens to end on.

How good it got, for how much training

Skill against total experience. A resume inherits everything its parent already learned, so the scale is cumulative rather than per-run. Hover a point for what that version scored and what changed to get there.

The family tree

Training did not run in a line. When a run came out worse than the model already shipped it was thrown away and the next one started again from the last good version — so the failures are dead branches, not steps along the way.

The same model, sixty games

One unchanged model played sixty fixed games. The spread is the reason training keeps its best checkpoint rather than its last: a single evaluation can land almost anywhere in this range.
